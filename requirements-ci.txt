# CI toolchain
# =====================================================================================
# Pinned to minor versions so a CI run six months from now resolves to something this
# project was actually tested against. An unpinned toolchain turns an unrelated upstream
# release into a mystifying red build on a PR that changed one comment.
#
# This file exists for a second reason: actions/setup-python's pip cache requires a
# dependency file to hash. Without one, `cache: pip` fails the job outright.
#
# NOTE ON dbt VERSIONS. These are the versions CI uses to LINT and PARSE locally on the
# runner. They are NOT the version that executes the project — Snowflake's dbt runtime is
# currently 1.9.4 and is not chosen here. Keeping the runner ahead of the runtime is
# deliberate: it surfaces deprecations early. It is also why the deprecation warnings this
# project emits must not be "fixed" — see the note at the top of dbt_project.yml.
dbt-core~=1.11.0
dbt-snowflake~=1.11.0

# Linting. sqlfluff uses the jinja templater against .sqlfluff-stubs/, so it needs no
# database connection and no dbt adapter at lint time.
sqlfluff~=3.5.0

# Deploys and executes the project object, and runs the verification queries.
snowflake-cli~=3.18.0
